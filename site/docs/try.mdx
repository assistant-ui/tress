# Try the browser demo


1. Open [the demo](/#demo) and start a conversation.
2. Choose its terminal connection action. It supplies the host address and
   secret session token for that conversation.
3. Install Tress with the command shown on the website, or build from source.
4. Run the copied connection command. For example:

```sh
tress attach https://your-demo.example -s YOUR_SESSION_ID
```

The URL and ID above are placeholders. Use the values from your own demo
session. The `-s` value is an access token, not just a public thread ID. Anyone
holding that command can join the session. The demo validates it internally;
no external auth service or `createTressAccess` setup is required. A bare host
address selects its default thread; `-s` selects a Tress demo session.

By default, this offers the terminal machine's whole filesystem, read-only.
Enter the printed pairing code under **connect folder** in this browser chat;
the terminal opens after pairing. Use `--root /path/to/project` to restrict the
scope, or `--chat-only` to join without offering files. Whole-filesystem access
includes personal files your terminal can read, subject to OS permissions;
symlinks and special files remain unavailable.

Send a prompt from the terminal. Its response appears in both clients. Close
the terminal to stop sharing. Run the command and pair again to resume access.

```text
/status      show connection and host details
/disconnect  stop sharing and exit (chat-only mode can /reconnect)
/exit        leave the terminal client
```

Add `--ui` to use the full terminal interface:

```sh
tress attach https://your-demo.example -s YOUR_SESSION_ID --ui
```

To restrict sharing to a real project folder from your computer or VM, use:

```sh
tress attach https://your-demo.example -s YOUR_SESSION_ID --root . --allow-write --ui
```

Run it in the project folder. Enter its pairing code under **connect folder**
in the same browser chat. The terminal UI opens after pairing; both clients
can then ask the agent to read and edit that folder. Omit `--allow-write` for
read-only access. `/exit` or `/disconnect` stops sharing. No shell execution is
exposed, and switching chats requires exiting first. The site must be reachable
from the machine running the command; `localhost` always means that machine.

The public demo has its own access model. To connect an application you own,
follow [existing apps](/docs/existing-app); adding a URL alone does not make
an arbitrary chat website compatible.
