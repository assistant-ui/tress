# Authentication & revocation


Use your existing authentication provider. Tress does not require a particular
login service. The app must turn both its browser session and its terminal
credential into a trusted user, connection ID, and expiration time.

Authentication identifies the user. Authorization decides whether that user
may read or write this particular thread. Check both on the server.

## Issue a separate terminal grant

After the user signs in through your app, issue a random, narrowly scoped
terminal credential. Store its hash, owner, allowed thread or workspace,
expiration, and revocation status. Keep provider and project-wide keys on
the server.

The preview CLI reads HTTP headers from a private JSON file. An example shape:

```json
{
  "Authorization": "Bearer APP_ISSUED_TERMINAL_TOKEN"
}
```

The placeholder is replaced by your application's credential issuance flow.
Custom application headers also work. Your server interprets them. On Unix,
the file must have private permissions, such as `chmod 600 app-headers.json`.
HTTPS is required except on loopback for local development or SSH forwarding.

```sh
tress attach https://chat.example.com/api/threads/main \
  --headers-file app-headers.json --ui
```

The client sends the headers on both stream and command requests, refuses
redirects, and does not forward them when switching to a different origin.
Credentials expire according to your app. Obtain a fresh file and reattach;
the preview does not implement OAuth or automatic token refresh.

## Revoke from your app

Persist the revocation, then notify each worker that owns an affected thread:

```ts
// Your authenticated application settings action:
await app.terminalGrants.revoke(connectionId, currentUser.id);
access.revoke(connectionId);
```

`app.terminalGrants.revoke` is application code: it must check ownership and
save the revocation durably. `access.revoke` closes that grant's active streams
and denies subsequent requests on this adapter. On restart, your `authorize`
callback must still reject the revoked credential.

The browser can continue because it has a separate session ID. Revocation does
not stop the host's agent or undo commands already admitted. If your application
also wants to stop a run, invoke its existing cancellation policy explicitly.

## Multiple workers

Broadcast revocation to every worker holding a stream for the grant. A database
update alone cannot close a stream on a different process. Route streams and
commands for a thread to the same owner. Each adapter also closes streams at
the grant's expiration, even when the thread is quiet.

A future managed access service may simplify credential issuance. It remains
optional and is not required by this integration.
