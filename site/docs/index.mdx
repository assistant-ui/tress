# One workspace, any interface.

Tress is a coding agent with a workspace that lives on your laptop, VM, or
server. Use the terminal or open its browser interface to work with the same
conversation and files. You do not need an existing assistant-ui application
to start a Tress workspace.

```text
Browser interface ──┐
                    ├── Machine host: agent + tools + workspace files
Terminal client ────┘          └── Harness conversation persistence
```

The host performs the work. Clients send requests and display the results.
For example, ask the terminal to create a file, preview that file in the
browser, and continue the conversation there. The file stays on the host's
disk; the browser does not need native filesystem or process access.

## Choose where to start

| You want to… | Start here |
| --- | --- |
| Work on your own project | [Run on your machine](/docs/workspace). Start the host in a folder, then use its terminal or browser interface. |
| Try Tress before running a host | [Try the hosted demo](/docs/try). The website supplies the agent and conversation host. |
| Continue conversations from an existing assistant-ui app | [Connect an existing app](/docs/existing-app). Keep its UI, agent, and identity; Tress becomes another client. |
| Embed the engine or connect your own interface | [Embedding and runtimes](/docs/embedding). Choose the engine, host, or client boundary you need. |

**Release status:** the durable machine host and existing-app discovery are
source previews. Build this checkout to use them. The installer currently
provides v0.3.0, whose local conversation is not saved after exit. See
[versions and limits](/docs/reference) before choosing an installation path.

## What survives closing a client?

Closing the browser or terminal disconnects that interface. The machine host
keeps running. Reconnect to continue the same conversation; restart the host
to restore saved completed turns. The standalone preview has one saved thread
per project. Recovery of a tool interrupted by a host crash is still unfinished.

Local mode saves Harness conversation snapshots on the machine. Optional
managed Harness stores the conversation remotely while execution and files
stay on the machine. Conversation persistence does not back up project files.
Use persistent disks and backups for those files.

## Connect an existing application

An existing assistant-ui app is another way to use Tress. Its backend already
supplies the agent and tools. Expose its authorized Harness threads and let
users attach from a terminal. They see the conversations their credential may
access without installing Tress browser components or moving execution to
their terminal machine. The app chooses API-key, anonymous, or custom access.
